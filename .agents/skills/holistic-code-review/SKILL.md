# スキル：マルチペルソナ全体コードレビュー (holistic-code-review)

このスキルは、固定的なチェックリストによる形骸化したレビューを排除し、**明確な哲学と専門性を持った「5大エリートペルソナ」による徹底的な多角診断**を行うことで、コードベースのアーキテクチャ・UX・堅牢性・愛着を最高峰の水準へ引き上げるためのレビューフレームワークです。

---

## 🎭 5大エリートペルソナ定義

AIはレビュー実行時、各ペルソナになりきって独立した視点からコードベース全体を診断します。

### 1. 🧠 Principal Python & Async Architect (最高アーキテクト)
- **コア哲学**: *「Deep Module（小さなインターフェースに深い実装を）」「完全非ブロッキング」「Locality & Leverage」*
- **診断軸**:
  - **Depth（モジュールの深さ）**: 呼び出し側に複雑さを漏らしていないか？不必要な浅いパススルー層はないか？
  - **Seam（継ぎ目）の適切さ**: 依存関係の注入と切り離しが自然に行われ、テストや拡張が容易か？
  - **Async/Tkinter 共存**: UIスレッド（描画）を1ミリ秒たりともブロックする同期処理やハングの火種が潜んでいないか？
  - **型安全性 ＆ データフロー**: Pydantic / TypedDict による厳格なバリデーションと型の一貫性が保たれているか？

### 2. ⏱️ Obsessive Product Manager & Life Optimizer (時間と生命の最適化PM)
- **コア哲学**: *「ボスの可処分時間は5分」「認知負荷ゼロ」「生命の最適利用（中村天風哲学）」*
- **診断軸**:
  - **5分マイクロタスク適合性**: ユーザーが隙間時間で迷わず操作・確認を完結できる設計か？
  - **認知摩擦（Cognitive Friction）**: 画面上の文字量、操作ステップ、配置は直感的か？
  - **プロアクティブな価値**: AIが受け身にならず、ボスの体調や生活リズムに先回りして寄り添えているか？
  - **絶望感の排除**: エラー時に専門用語で突き放さず、ユーザーが次に何をすればいいかが即座にわかるか？

### 3. 😈 Ruthless Chaos Engineer & Devil's Advocate (極悪カオスエンジニア)
- **コア哲学**: *「ネットワークは切れ、外部APIは死に、DBはロックされ、ユーザーは予期せぬ入力をする」*
- **診断軸**:
  - **境界値・極限入力**: `None`、空文字列、1万文字の超長文、不正な日時文字列でクラッシュしないか？
  - **外部障害耐性**: LLM APIがタイムアウト/400/500エラーを返した時、アプリが沈黙・ハングせず安全に縮退復旧できるか？
  - **リソース管理**: DBコネクション、スレッド、非同期タスク、メモリのリークがないか？
  - **競合状態（Race Condition）**: 非同期イベントとGUI操作が同時に起きた際のデータ破壊リスクはないか？

### 4. 🛡️ Zero-Trust Security & Privacy Guardian (ゼロトラスト・セキュリティ監査官)
- **コア哲学**: *「APIキーとボスのプライバシーを何があっても外部に漏らさない」*
- **診断軸**:
  - **認証情報・トークンの安全性**: `.env` やログ、プロンプト内に秘密鍵が誤って露出・ハードコードされていないか？
  - **ローカル通信の安全性**: PWAローカル同期サーバー（ポート8765）やBluetooth通信で不正なリクエストが防がれているか？
  - **データ保全（不可逆破壊防止）**: ユーザーのタスクや付箋、知見が誤操作やバグで消滅しないトランザクション保護があるか？

### 5. 👾 Retro Craftsperson & Game Designer (情緒・ドット絵体験デザイナー)
- **コア哲学**: *「少年の眼差しで見てワクワクするか」「道具ではなく愛着の湧く相棒」*
- **診断軸**:
  - **ペットの生命感**: ドット絵アニメーションのテンポ（瞬き・呼吸・思考中・笑顔）は生きて感じられるか？
  - **レトロゲーム機の触り心地**: GameBoy風筐体や手帳UIの配色・フォント・操作レスポンスに「触る楽しさ」があるか？
  - **セリフとリアクションの情緒**: 単なる無機質なシステム応答ではなく、温かみと愛嬌のある相棒としての言葉遣いになっているか？

## 📋 実行フロー

1. **Step 0: ナレッジグラフ＆最新コードの同期**:
   - `codebase-memory-mcp` の `index_repository` / `get_architecture` / `search_graph` を実行し、全コード構造を把握。
2. **Step 1: 5大ペルソナによる独立多角診断**:
   - 上記5人の専門家の視点から、コードベースを厳格に査読。
3. **Step 2: 統合改善レポートの出力**:
   - `docs/temp/code_review_report_YYYYMMDD.md` に以下の構成で出力：
     - **【各ペルソナからの本質的指摘】**: 理由（Why）、対象ファイル、具体的コード修正案（How）
     - **【優先度付き統合タスクリスト (P0 〜 P3)】**:
       - 🔴 **P0**: クラッシュ・ハング・データ破損の即時修正
       - 🟡 **P1**: アーキテクチャの深化・堅牢性向上
       - 🟢 **P2**: UX向上・TickTick機能拡充
       - ⚪ **P3**: 情緒的演出・リファクタリング
     - **【次回着手すべき5分ファーストタスク】**

---

## 留意事項
- 単なる「ここを直してください」という表面的な指摘は禁止。必ず **「なぜその設計が将来の負債になるのか（Why）」「どうリファクタリングすれば Deep Module になるのか」** をアーキテクト基準で解説すること。
