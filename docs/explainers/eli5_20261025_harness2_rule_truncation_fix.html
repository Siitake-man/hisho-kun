☕ 初級エンジニア向けの物理解説

🎒 身近な日常の例え：胸ポケットと本棚の整理
AIの常駐ルール枠は、いわば**「作業着の胸ポケット」**です。ここに入れたメモは、AIが作業中いつでも0秒でチラ見できます。
しかし、胸ポケットにはサイズ限界（約24KB）があります。

以前の状態は、「胸ポケットに厚さ10cmの辞書（13.6KBの英語テスト手順マニュアル）を無理やり突っ込んでいた」状態でした。その結果、ポケットからあふれ出た「一番大事な緊急連絡先や鍵（#JEV, #CLOUD, OpenCode規約）」がボロボロと地面に落ちて見えなくなっていた（Truncated）のです！

💡 なぜGoogle Harness²がこの問題を解決できたのか？

Googleの研究チームが作った Harness² の中核には、まさにこの物理現象を防ぐための always_on_max = 24,000 という絶対防壁がありました。

  • Surface 分離の原則: 普段使わない専門マニュアル（辞書）は胸ポケットに入れず、「本棚（スキル `SKILL.md`）」へ置く。
  • 胸ポケットにはトリガーだけを書く: 胸ポケットには「◯◯の時は本棚の◯◯スキルを見よ」という1行だけを忍ばせる。
  • 自己改善ループ（Cue / Lesson / Evidence）: ルールが太ったりエラーが出たら、機械的に文字数を測って自動でポケットを整える。

📖 登場した専門用語の完全解体辞典

常駐ルール（Always-On Context）とは？
AIエージェントがユーザーと会話する際、毎ターン必ずシステムの裏側でプロンプトの先頭に自動注入される前提知識のこと。
Antigravityでは GEMINI.md と AGENTS.md がこれに該当します。手動で読み込まなくても最初から知っている反面、長すぎるとAIの思考予算（コンテキストウィンドウ）を圧迫します。
トランケーション（Truncation / 切り捨て）とは？
システムがメモリ不足やトークン溢れを防ぐため、一定の文字数（Antigravityでは約23.5〜24KB）を超えた長文ルールの末尾をバッサリ切り捨てる現象。
切り捨てられた部分はAIから完全に不可視になるため、「書いたはずのルールをAIがなぜか平然と無視する」という不可解な現象の真因となります。
Harness²（ハーネス・スクエア）とは？
Google Research が 2026年4月に公開した、AIモデル自体の重みを変えずに、プロンプト・ガードレール・スキル・スクリプト（ハーネス）側を自己進化させるフレームワーク。
「タスク実行 ➔ 失敗・摩擦の検知 ➔ 経験則（Cue/Lesson/Evidence）の抽出 ➔ ルール/スキルの自動書き換え」を自律的に繰り返します。
Cue / Lesson / Evidence（経験則の3点セット）とは？
Harness² がルールを自己改善する際に必ず出力する構造化フォーマット：
  • Cue（発動条件）: 「どんな場面・入力で問題が起きたか」
  • Lesson（改善行動）: 「どのルールのどの手順をどう変えるべきか」
  • Evidence（根拠）: 「どんな測定結果・エラー解決でその有効性が実証されたか」
