② 物理構造の解説 — なぜ気づけなかったのか

🚪 権限ダイアログは「アプリの内側」にある

OpenCode が「⚠️ 権限が必要です」を出している間、エージェントは完全に停止しています。 停止しているのはアプリの内部イベントなので、秘書くんからは見えません。 だから外から見えないなら、内側から知らせてもらう——これが今回の答えです。

🎭 身近な例え: 「受付の呼び出しベル」

役所の窓口で、職員が「上司のハンコ待ち」で止まっているとします。 待合室のあなたは気づけません。そこでハンコ待ちになった瞬間に受付ベルが鳴るようにしたのが今回のプラグインです。 ベルは「ハンコを押す」代わりにはなりません（＝判定には干渉しない）。気づかせるだけが役割です。

🔍 観測点は「評価の瞬間」

OpenCode は全ツール実行前に権限を評価し、その結果を effect: "ask" として持ちます。 Plugin はこの評価の瞬間に割り込み、ask のときだけ通知します。 allow（自動許可）で鳴らすとベルが鳴りっぱなしになるため、フィルタは必須です。

⚡ 非ブロッキングという設計

通知APIには wait_decision:false を付けます。付けないと最大180秒応答が返らず、 Hookのtimeout（5秒）で殺されます。これが「通知が来ない」最有力の原因でした。 「知らせる」と「待つ」は分離するのが設計の要諦です。

③ 専門用語の完全解体辞典

Plugin（プラグイン）— OpenCode の拡張点

OpenCode 本体に手を入れずに、イベントの監視やツールの追加ができる仕組み。~/.config/opencode/plugins/ に置くだけで読み込まれ、 ファイルを保存すると自動で再読み込みされます（再起動不要）。Antigravity の Hook に相当します。

PreToolUse Hook（Antigravity 側）

Antigravity が「ツールを使う直前」に外部スクリプトを呼ぶ仕組み。.agents/hooks.json で定義します。 OpenCode には同等の Hook が無いため、代わりに Plugin を使います。

permission.hook("evaluate") — 権限評価の観測点

OpenCode V2 の Plugin API。権限が評価される瞬間に呼ばれ、イベントに action（種別）、 resources（対象コマンド）、effect（判定）が入っています。判定を書き換えることも可能ですが、 今回は観測のみ（＝権限判定に一切干渉しない）に徹しました。

effect（allow / ask / deny）

権限評価の結果。allow=無承認で実行可、ask=人間の承認待ち、deny=即遮断。 ask のときだけ通知するのがスパム防止の鍵です。

wait_decision: false — 非ブロッキング通知

秘書くんの通知APIのオプション。false なら即座に {"status":"queued"} を返します。 true（既定）だと人間の回答まで最大180秒待つため、HookやPluginを道連れに停止します。

Bearer 認証（.sync_token）

秘書くんの全POST APIはトークン必須（ゼロトラスト）。トークンはリポジトリ直下の .sync_token にあります。 付け忘れると 401 で無音失敗します。

ループバック限定（/api/agent/*）

承認要請・通知の作成APIは localhost からのみ許可されます（外部からは403）。 LAN上の攻撃者がトークンを盗んでも「自作リクエスト→自己承認」が成立しないようにする防御です。

逆allowlist方式（Antigravity での代替）

Antigravity の PreToolUse には「ask か allow か」の情報がありません。 そこで「安全と断定できるコマンド以外は通知する」という近似で対応します（クールダウンで過剰通知を抑える）。

確率的ソフト層 / 決定論的ハード層（二層防御）

Jev（System One）はミリ秒で危険を弾く確率的な層。確信度が低いこともあります（実測: git reset --hard を確信度0.39でdeny）。 そこで permissions（Hard ACL）が決定論的に最終保証を担います。 「確率に頼る層」と「決定論で守る層」を混ぜないのが今回の第一原理です。

ドリフト検知（model_catalog.py --check）

モデル提供は頻繁に変わります（実測: キャッシュ37件中10件が既に廃止済み）。 推奨モデルの廃止・新モデルの出現・価格改定を機械検知し、 ボスが model_policy.json に1行追記するだけで追随できるようにしました。

④ まとめ — 今回の設計を1枚で

層役割実装性質
① 遮断危険を止めるpermissions（Hard ACL 51ルール）決定論的・必ず効く
② 選抜手札を選ぶJev（System One）確率的・ミリ秒・約0.05円
③ 気づき人間を呼ぶPlugin → ask_input（非ブロッキング）ask のときだけ・観測のみ

「止まっていることに気づけない」をゼロにする — これがネオ秘書くんの存在意義そのものです。
