🎭 2. 身近な例えでの物理構造解説

🏢 身近な例え: 「無人のオフィスの照明」と「人感センサー」

従来のWebアニメーションは、部屋に誰もいない（スマホの画面がOFF・別アプリを開いている）深夜でも、 天井の蛍光灯とエアコンを全開（毎秒60回フル稼働）にして電気代を垂れ流していました。
これでは古いスマホのバッテリーが急速に消耗し、ホカホカに発熱してしまいます。

本改修の「適応型描画ループ」は、人感センサーのようなものです。 誰も見ていない時は即座に全電源を遮断（0fps完全停止）。 誰かがドアを開けた時（画面復帰）や、呼び鈴を鳴らした時（タスク完了の通知・なでなでタップ）だけ、 瞬時に必要な光を灯します（Wake-on-Demand）。

🚨 なぜ cancelAnimationFrame による保留破棄が必須なのか？

ただ単に「非表示だから次のフレームを呼ばない」だけでは不十分です。 ブラウザはすでに「次の描画予定（保留中チケット）」をキューに抱えています。 タブを素早く切り替えた際、古い保留チケットが残ったまま復帰処理が走ると、 チケットが2重に発券されて 120fps の超高速多重ループに暴走します。
そのため、画面が隠れた瞬間に cancelAnimationFrame(animFrameId) でチケットを粉砕することが、プロフェッショナルなカオス防御です。

// 🛡️ 画面非表示になった瞬間に保留フレームを即時破棄 function stopParticleLoop() { if (animFrameId !== null) { cancelAnimationFrame(animFrameId); // キューを完全消去 animFrameId = null; } isParticleLoopRunning = false; // 0fps完全停止 }

📚 3. 登場した専門用語の完全解体辞典

1. requestAnimationFrame (rAF)
ブラウザがディスプレイの描画タイミング（通常1秒間に60回、約16.6ミリ秒ごと）に合わせて関数を呼び出す仕組み。 setTimeout と違ってディスプレイの更新（VSync）と完全に同期するため、カクつきのない滑らかなアニメーションが描画できます。
2. cancelAnimationFrame
requestAnimationFrame で予約した「次の描画予定チケット」を取り消すコマンド。 画面が非表示になった瞬間に未実行の予約を取り消すことで、CPUやGPUの無駄な処理を1ミリ秒も走らせないゼロ消費を実現します。
3. Page Visibility API (document.hidden)
ユーザーがブラウザのタブを切り替えたり、スマホの画面をスリープさせたりして「現在そのWebページが見えているかどうか」を判定する標準ブラウザ機能。 document.hidden === true で非表示を検知し、visibilitychange イベントで状態変化をリアルタイムに受信できます。
4. Wake-on-Demand (オンデマンド復旧)
普段は0fpsで完全に眠らせておき、ユーザーのタップ（なでなで）やAIエージェントのタスク完了通知など「描画が必要なイベントが発生した瞬間」だけループを叩き起こして再開する設計思想。
5. Deep Module (深いモジュール)
John Ousterhout 教授が提唱した設計思想。「外から見える操作（インターフェース）はシンプルで小さく、内部の実装や保護機構が極めて深いモジュール」のこと。 外部は wakeParticleLoop() を呼ぶだけで、多重起動防止や非表示判定などの複雑なライフサイクルが安全に完結します。
