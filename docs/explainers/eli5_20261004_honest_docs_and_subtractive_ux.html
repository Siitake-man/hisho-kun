「なぜスマホUIに文字入力欄がないのに、音声入力を案内してしまったのか？」——形骸化したドキュメントの真因と、ワンタップ承認特化の物理構造を解剖する。

💡 2. なぜこの矛盾が生まれたのか？（第一原理の反省）
🏢 身近な例え：エレベーターの押しボタン

エレベーターに乗ったとき、やることは「行きたい階のボタンを1回押す」だけです。ここに「キーボードを繋いで行先を手書き入力することもできます」というマニュアルがあったらどう思うでしょうか？
「そもそもキーボードを挿す穴もないし、ボタン押すだけで済むのに何を入力させる気だ？」 と全員が困惑します。今回の「スマホ音声入力」がまさにこれでした。

ネオ秘書くんのスマホPWAは、「PCから飛んできた承認要求をワンタップで片付けるリモコン」 です。文字を打ち込む入力フォームは最初から存在しません。

しかし過去に重いWhisperを撤去した際、開発チーム（AI）は「撤去したけれどスマホの音声入力があるから代替できる」という 自己満足の言い換え をドキュメントに残してしまいました。これがボスの「そもそも入力が必要な画面がないでしょ？」という一撃で見事に看破されたのです。

📖 3. 登場した専門用語の完全解体辞典
引き算の美学 (Subtractive Design) ▼
機能を増やすのではなく、不要なものを削ぎ落とすことでコアの価値（認知負荷1秒のワンタップ承認）を研ぎ澄ます設計思想。「スマホで長文を打たせる」のではなく、「スマホでは1秒見るだけで済む」ようにすることが真の生産性向上。
MediaSession API (メディアキー連携) ▼
スマホのブラウザで音楽再生をエミュレートし、イヤホンやスマートウォッチの「再生/一時停止ボタン」をリモコンとして傍受するWeb標準技術。「音量キー」はセキュリティ上ブラウザから取得できないため、正しくはメディアキー（再生/一時停止）を使うのが物理的真実。
cancel_pending (保留自動消去) ▼
スマホで承認する前にPC側で先にキーボード操作（y/n）された場合、スマホ側に残っている待機カードを即座に消去する同期プロトコル。スマホをいちいち手動で閉じる手間をゼロにする。
Air-Gapped Local LLM (LFM2.5) ▼
外部インターネット通信を完全に遮断（Air-Gapped）した状態で動く軽量ローカルAI。わずか230MBのメモリフットプリントで、APIキーも通信料も外部漏洩リスクもゼロで動作する。
