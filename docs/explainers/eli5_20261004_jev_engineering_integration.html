🏢 身近な例え：超高給エリートと高速専任受付

【従来の姿（巨大LLM単独）】
時給3万円のシニア建築士に「この書類は総務部？それとも開発部？」「鉛筆削っていいですか？」という1秒のYES/NO確認を何百回も相談している状態です。建築士は毎回、会社の全社規程集（巨大ルール）を最初から最後までめくってから返事をするため、待ち時間も費用も莫大になります。

【Jev導入後の姿（二重知能）】
入口に月給数千円の「超高速な専任受付（Jev）」を配置。仕分け、危険物チェック、部署ルーティングは受付が100ミリ秒で即決。シニア建築士（フロンティアLLM）には「本当に設計図を描く仕事」だけを渡します。

⚙️ 物理構造の真実：KVキャッシュとコンテキストの壁

LLMが文字を出力する際、毎回過去の全履歴（コンテキスト）をメモリ（KVキャッシュ）上に展開して行列計算を行います。

  • 盲目ルーティングの罠: エージェント間でバトンタッチ（引き継ぎ）するたびに、過去の全履歴が別のモデルへ丸ごと転送され、再計算の二重課金が発生します。
  • Jevの物理的強み: Jevはテキストを生成（執筆）しません。State（状態）を受け取り、重み固定の分類ネットワークで「確率ベクトル」を一発で計算して返すだけなので、GPUメモリを占有せずミリ秒で完了します。

⚡ Speculative Fan-out（推論ファンアウト）
コスト削減の奥義
【定義】: 1つの入力データ（State）に対して、複数の独立した質問（例：「どこの部署？」「緊急度は？」「返金希望か？」）を単一のHTTPリクエストで一括送信し、並列計算させる技術。
【Why（なぜ効くか）】: 質問ごとに個別にAPIを呼ぶと、毎回State（チケット本文など）の転送・再パースが発生します。1回にまとめることで、13個の質問を個別実行するより12.2倍安く、10倍速くなります。
【注意点】: 質問同士が前回の答えに依存する場合は一括化できません（前の結果が必要な場合は分割する）。
🎯 RLCD (Reinforcement Learning for Calibrated Decisions)
Jevの訓練原理
【定義】: 「校正された決定のための強化学習」。モデルが出力する「確信度（90%など）」が、実際の正解率と完全に一致するように訓練する手法。
【LLM（RLHF）との違い】: 通常のChatGPTやClaudeは「人間を喜ばせる（RLHF）」ように訓練されているため、自信満々に嘘をつきます（確信度95%と言いながら間違える）。Jevは「90%と答えたら、本当に100回中90回当たる」という**正直な確率（Calibrated Confidence）**を出力するため、プログラム側で「95%以上は即自動化、未満は人間へ」という自動分岐コードが組めます。
🗂️ Tiered Tools（ツールの階層化開示）
コンテキスト節約
【定義】: エージェントが使えるツールが数十〜数百個ある場合、最初から全てのJSON引数定義（スキーマ）を渡さず、「1行の名前と説明だけ」を渡し、ツールを使うと決めた瞬間だけ詳細スキーマを開示する二段階方式。
【効果】: ツール定義だけで数万トークンを食い潰し、モデルの推論を鈍らせる「コンテキスト汚染」を防止します。
🚪 Exit Option（逃げ道の必須化）
Jev質問設計の掟
【定義】: Jevに選択肢（Choice）を与える際、必ず "other" や "none"（どれにも当てはまらない）という選択肢を配列に含める設計規則。
【Why（なぜ必須か）】: Jevは与えられた候補の中から必ずどれか1つを選ぼうとします。逃げ道がないと、想定外の入力が来た時に「最も近い全然違う選択肢」を無理やり選んでしまい、重大な誤作動の原因になります。迷ったときは other を選ばせ、次のレイヤー（LLMや人間）にパスさせます。
🛡️ 4-Layer Cascade（4層カスケード防御）
システム全体の鉄則
【定義】: エージェントの全判断を4つの階層に流し込み、確信が得られた最も浅い層で即座に処理を確定させる設計思想。
1. Code (0円・0ms): 日時計算、文字列一致、ハードACLなど確実なルール。
2. Jev (極小・100ms): 閾値（95%等）以上の確信度を持つ定型判断・ルーティング。
3. LLM (Kimi K3等・数秒): Jevが迷ったケース（<95%）や、長文理由付け・画像読解が必要な処理。
4. Human (ボス・可処分時間): ファイル削除・本番デプロイ等の不可逆操作、および両者が迷ったケース。
