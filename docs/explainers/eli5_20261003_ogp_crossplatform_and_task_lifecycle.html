② Tkinterの壁と二段階クロスプラットフォームADR（DESIGN_SPEC §6.0）

「なぜ重たいElectron（150MBのChromiumメモリ喰い）に書き換えないのか？」「LinuxやMacでのウィンドウ透過はどうするのか？」
Grokやシリコンバレーのレビューで指摘されたTkinterの描画限界に対し、ネオ秘書くんが下した「引き算の美学」と二段階移行パスを解剖します。

🖥️ PCデスクトップ層 Tkinter (超軽量)

  • 常駐メモリ: わずか 30〜50MB
  • 役割: トレイ常駐・透過キャラ・最小限の通知
  • スマホ接続時: 自動最小化（withdraw）で画面占有ゼロ
  • OS差異: Windows/Mac/Linux で透過APIが壊れても、メイン業務はスマホへ退避済みのため影響なし

📱 スマホPWA層 (卓上リモコン) Web標準 (HTML/CSS/JS)

  • 画面占有ゼロ化の主役（古いスマホを卓上ディスプレイへ）
  • スプリング物理・アニメーション・TODO・承認ボタンを完備
  • iOS / Android の全ブラウザで 100% 同一描画
  • 将来の移行時: この資産（web_pet/）がそのままPCアプリの中身になる

⚙️ Agent Bridge ＆ Zero-Trust Python Async Native

  • Claude Code / Cline / OpenCode の承認要求を中継
  • 同一LAN / Tailscale 上で暗号照合（Bearer Token）
  • PC解決時のスマホ待機カード即時自動消去 (cancel_pending)
  • 描画方式が変わっても、このバックエンド層は1行も壊れない
💡 身近な例えでの理解（トラックの運転席と荷台）:
Tkinterを無理やり魔改造して豪華な3DやリッチUIを積むのは、「軽トラックの運転席に大理石のオフィスを作ろうとする」ような無謀な行為です。ネオ秘書くんは、オフィス（リッチUI）をすべてスマホという外付けディスプレイへ引っ越しさせ、トラック（PC）はエンジンと通信だけに徹させました。これが世界水準レビューで高評価を得た「二段階ADR」です。

💡 身近な例えでの理解（通し番号伝票 vs 手書き日付）:
伝票整理で「令和8年10月3日午後」と「2026/10/03」が混在すると、自動仕分け機はエラーで止まってしまいます。一番確実なのは、発行順に「0001, 0002, ...」と通し番号（ミリ秒整数）を機械的に刻印することです。

📖 登場した専門用語の完全解体辞典（クリックで開閉）

本セッションで登場したアーキテクチャ・プロトコル用語を初心者にも腹落ちする言葉で解説します。

1. OGP (Open Graph Protocol) ▼
SNS（X/Twitter、Facebook、Slack、Discord）にWebサイトのリンクを貼り付けた際、自動的にリッチなタイトル・概要・画像カードを表示させるための世界共通メタデータ規格です。
2. ソーシャルプレビュー (Social Preview) ▼
GitHub等のリポジトリ設定画面で登録する、SNS共有時の看板画像（推奨1280×640ピクセル）。未設定の場合は味気ないリポジトリ名だけの文字カードになりますが、看板を設定すると一目でプロダクトの世界観が伝わります。
3. ADR (Architectural Decision Record) ▼
「なぜその設計・技術を選び、なぜ他方を却下したのか」という技術的意思決定の背景・理由・トレードオフを公式に記録した文書。「なんとなく動いたから」ではなく、1年後の自分が読んでも納得できるように残す設計の意思決定ログです。
4. Tauri (タウリ) ＆ pywebview ▼
デスクトップアプリを作成するための次世代フレームワーク。重たいブラウザ丸ごと（Chromium）を内包するElectronと異なり、OS標準のWebView（Edge/Safari）とRustまたはPythonを直結するため、数MBの極小サイズと超軽量動作を実現します。
5. Pydantic (パイダンティック) ▼
Pythonにおいてデータの型（数値、文字、真偽値等）が正しいかを実行時に厳格にチェックする型バリデーションライブラリ。想定外の文字列やNoneが混入した瞬間にエラーを検知し、バグの侵入を防ぎます。
6. Unix Epoch (エポックミリ秒) ▼
1970年1月1日午前0時0分0秒（UTC）からの経過時間をミリ秒単位の数値で表した時刻表現。タイムゾーンや言語フォーマットの違いに惑わされず、単純な引き算だけで「何秒前」「どちらが先か」を計算できる標準形式です。
7. 知見ID 53（手帳リスト分離規約） ▼
秘書くんアプリ内でTODOや宿題を起票する際、ボスのプライベートTODOや未分類タスク（list_id=1等）と混ぜず、必ず専用の「秘書くん開発」（list_id=6）へ隔離して登録するプロジェクト恒久ルールです。
