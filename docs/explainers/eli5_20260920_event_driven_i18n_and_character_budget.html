2. 身近な例えでの理解：劇場の看板付け替え

「舞台の幕を下ろさずに、客席から見えるすべての看板を一瞬で英語に変える」

  • 課題: 通常のデスクトップアプリは、言語を切り替えると「アプリを再起動してください」と要求します。これはメニューやウィンドウが起動時に一度だけ文字列を固定生成してしまうからです。
  • 解決策（イベントリスナー）: 支配人（set_language）がベルを鳴らすと、劇場の各担当（メイン窓、トレイ、手帳）が一斉に待機していた関数（リスナー）を走らせ、客席（ユーザー）に気づかれないミリ秒単位で看板を差し替えます。
  • Character Budget（文字数予算）の鉄則: 日本語「設定」（2文字）を英語「Settings」（8文字）に直訳すると枠を突き破ります。スマホのボトムドックでは「Config」（6文字）へと圧縮し、デスクトップ吹き出しでは幅を 220px〜320px に動的伸縮させることで、レイアウト崩れ（UI窒息死）を完全に防ぎます。

3. 専門用語の解体辞典（クリックで展開）

イベント駆動（Observer パターン / Subscribe）

「何かが起きたら登録された関数を一斉に呼ぶ」仕組み。呼び出し側は誰が登録されているか知る必要がなく、部品同士の結合をバラバラ（疎結合）に保てる設計パターンです。

Character Budget（文字数予算）

画面のボタンや枠のサイズから逆算し、「この領域には最大何文字までしか入れない」と決めるUI設計ルール。英語化で文字数が1.5倍に膨らむWeb/スマホ開発で必須の概念です。

辞書完全対称性（Dictionary Symmetry）

多言語化において、日本語（ja）にあるすべてのキーが英語（en）にも1個の狂いもなく存在すること。今回のテストでは全86キーが完全に対称であることを単体テストで自動保証しています。

Fail-Closed フォールバック

万が一、英語の翻訳が見つからない（KeyError）場合でもアプリを落とさず、安全に既定言語（日本語）を表示し、最悪でもキー文字列そのものを返す二重防壁のことです。
