🏢 2. なぜこの設計なのか？（身近な例えと第一原理）

身近な例え：「引越し先の新築オフィス」と「金庫」

会社で「新しいオフィスビル（NeoHisho.exe）」を建てて引っ越したとします。

ビル自体はまっさらな新築ですが、社員の個人データや顧客カルテ（カレンダーやTODO）は、ビルの壁の中ではなく、「中央金庫室（%LOCALAPPDATA%）」に保管されています。

だから、ビルが新しくなっても、社員が席に着けば元のカルテがそのまま開けます。

エンジニア視点：なぜEXEの中にDBを入れないのか？

もしEXEと同じフォルダにDBを同封してしまうと：
1. アップデート時にデータが消える：新バージョンを上書き解凍した瞬間に、ユーザーの予定やタスクが初期化されて大事故になります。
2. Program Filesの権限問題：管理者権限フォルダに解凍された場合、書き込み権限エラーで起動直後にクラッシュします。
そのためChromeやVS Codeと同様に、データは必ず %LOCALAPPDATA% に逃がすのがプロの鉄則（ADR-2）です。

📚 3. 本日の専門用語 完全解体辞典

1. ADR-2 (データ境界ポリシー) ▼
何をするものか： 暗号鍵、トークン、SQLiteデータベースを「OneDriveやDropbox等のクラウド同期フォルダ」から構造的に締め出し、Windowsの非同期領域（%LOCALAPPDATA%\NeoHisho）に固定するアーキテクチャ規約。
なぜ必要か： クラウド同期フォルダにDBを置くと、Git漏洩リスクに加え、同期遅延によるSQLiteファイル破損（ロック競合）が多発するためです。
2. Single Instance Lock (ポート 54321 による多重起動防止) ▼
何をするものか： 2つ目の秘書くんが起動しないように、起動時にローカルのポート 54321 を占有（bind ＋ listen）する仕組み。
なぜ必要か： 2つのプロセスが同時に同じSQLiteデータベースや同期サーバー（ポート 8765）を開こうとするとデータ破壊が起きるため、2重目のプロセスは画面を出さずに即座に終了（return）します。
3. Windowed Subsystem (console=False) の罠 ▼
何をするものか： PyInstallerでビルドする際、黒いコマンドプロンプト画面を表示させない一般的なGUIアプリ設定。
遭遇した事象： 黒い画面が出ない反面、起動時にライブラリ不足やエラーが発生しても、標準出力・標準エラーが os.devnull（ゴミ箱）に消えてしまい、「何も起きずに無言で終了した」ように見えてしまう特徴があります。
4. overrideredirect(True) と透過ウィンドウ ▼
何をするものか： TkinterでWindows標準のタイトルバーや閉じるボタンを撤去し、デスクトップ上にキャラクターを直接浮かび上がらせる手法。
特徴： Windowsの仕様上、標準のウィンドウ枠を持たないため、タスクバーのアイコン一覧には現れず、PowerShellの MainWindowHandle も 0 になります。
