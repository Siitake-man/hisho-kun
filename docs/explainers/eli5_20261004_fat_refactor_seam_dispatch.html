🏢 第2層: 初級エンジニア向けの物理解説（Why & What）

なぜ2,000行を超えたコードは死ぬのか？そしてSeam技法はどうやって安全に手術したのか？

🏚️ ワンオペ百貨店の崩壊（分割前の物理）

分割前の local_sync_server.py は、例えるなら「1人の店員が正面玄関の警備、案内所、レジ、在庫管理、調理、配達まですべてこなす巨大百貨店」でした。

  • if-elif のスパゲッティ地獄: do_POST だけで500行を超え、上から下まで20個以上の elif path == '...' を直列に評価。1行書き換えるだけで他のエンドポイントが壊れる恐怖。
  • 認可判定の漏れリスク: 「このAPIはループバック専用か？」「トークンが必要か？」が if 文の奥深くに散乱し、審査漏れ（RCEの隙）が生じやすい構造。
  • AIのコンテキスト圧迫: 1つのバグを直すだけで 2,300行全文をAIが読み込むため、推論トークンを大量浪費しハングの原因に。

✨ 専門フロアと総合案内所（Seam分割の物理）

今回のリファクタでは、Michael FeathersのSeam（縫い目）技法を適用し、百貨店を完全に近代化しました。

  • 総合受付（RouteRecord）: 入口の do_POST はわずか20行！すべての道案内は1つの「ルートテーブル辞書」で管理され、auth_level に応じて自動でゲート番（認可）がチェックします。
  • 看板（Facade）はそのまま: 外部のテストやモジュールから見たインポート看板（from local_sync_server import get_bridge_hub）は1文字も変えずに再エクスポート。既存のテストスイートは1行も壊れません。
  • 専門フロア（Deep Modules）: 認証は auth_checks.py、エージェント中継は agent_bridge_hub.py、キャッシュは status_cache.py と、それぞれが独立してテスト可能な深いモジュールへ進化しました。

📚 第3層: 専門用語の完全解体辞典

クリックすると詳細が開きます。アーキテクトとしての語彙力を鍛えましょう。

1. Seam（シーム / 縫い目）技法 ▼
レガシーコード改善の古典『Working Effectively with Legacy Code』で提唱された最重要概念。
「その場所のコードを直接書き換えることなく、プログラムの振る舞いを変更・テスト・分離できる場所」のこと。
今回は、巨大クラスの内部ロジックを独立関数・別モジュールへ切り出し、元の場所からは「呼び出すだけ」の縫い目を作ることで、既存の振る舞いを一切壊さずに安全な外科手術を完遂しました。
2. Facade（ファサード）パターン ＆ 再エクスポート ▼
フランス語で「建物の正面」を意味します。内部がどれだけ細かく分割されても、外部の利用者に対しては「おなじみの正面玄関」を提供し続ける設計。
local_sync_server.py に from server.agent_bridge_hub import AgentBridgeHub を置くことで、何百もある既存の単体テストや外部スクリプトの patch("local_sync_server.AgentBridgeHub") を1行も書き換えることなく100%の互換性を担保しました。
3. テーブル駆動ディスパッチ（Table-Driven Dispatch） ▼
何十個もの if path == '/a': ... elif path == '/b': ... を連ねる代わりに、{"/a": HandlerA, "/b": HandlerB} というデータテーブル（辞書）を定義し、キー検索で一発で処理を呼び出す設計手法。
コードの行数が激減するだけでなく、新しいAPIを追加する際もテーブルに1行足すだけで完了し、分岐の漏れやタイポが構造的に排除されます。
4. キャラクトライゼーションテスト（仕様確定テスト） ▼
「正しい仕様が何か」を問うのではなく、「今現在のシステムの実際の振る舞い（Character）をそのまま固定して保護する」ためのテスト。
Phase F0で tests/test_server_seam_characterization.py を敷設し、分割前の各関数の戻り値・引数・例外の挙動を網羅的にピン留めした上でリファクタに着手したため、1つのデグレも生じずにALL GREENで完走できました。
5. ゼロトラスト Loopback 境界防御 ▼
「社内LANやローカルPCからの通信だから安全だろう」という甘えを排し、すべての通信の出自を厳格に検証する防犯設計。
特にエージェント承認API（/api/agent/approval）はPC上でコマンドを実行させる強大な権限を持つため、送信元IPが厳密に 127.0.0.1 または ::1 であることを RouteRecord の認証ゲートで機械的に強制。LAN内の他端末からの悪意あるパケットは、ハンドラに届く前に即座に 403 Forbidden で撃墜します。
