## 1. バージョン定数一元化（version.js）の設計調査

### 1.1 現状の課題分析（バージョンの不整合リスク）
現在、プロジェクト内には複数箇所にバージョン情報やキャッシュ識別子が散逸しています。

| 対象ファイル | 設定値・形式 | 役割 | 課題・リスク |
|---|---|---|---|
| `version.py` | `__version__ = "1.0.0"` | Python側の Single Source of Truth | 正式なアプリバージョン。 |
| `web_pet/sw.js` | `const CACHE_NAME = 'neo-pet-v5.32';` | PWA Service Worker キャッシュキー | PWA更新時に手動変更が必要で、`pet.js`・`index.html` との乖離が懸念される。 |
| `web_pet/pet.js` | `if (key !== 'neo-pet-v5.32')` | 古いPWAキャッシュパージ許可キー | `sw.js` の `CACHE_NAME` と不整合を起こすとキャッシュが不正削除/永続化する。 |
| `web_pet/index.html` | `<script src="*.js?v=5.32">` | スクリプトのキャッシュバスティング | HTML内の8つの script タグで `?v=5.32` が直書きされており、手動更新漏れが発生しやすい。 |
| ドキュメント類 | `README.md`, `INSTALL_GUIDE.md` 等 | ユーザー向け配布バージョン (v1.0.0) | Web PWAの内部アセットバージョン (v5.32) と二重管理状態。 |

### 1.2 解決設計案（動的配信 ＆ `version.js` 一元化メカニズム）

#### アーキテクチャ方針
1. **Single Source of Truth**: Python側の `version.py` 内 `__version__`（例: `"1.1.0"`）およびコミットハッシュ/ビルド番号を唯一の基準とする。
2. **動的 `version.js` エンドポイント**:
   `local_sync_server.py`（または `DeskPetSyncHandler`）において、`/web_pet/version.js` または `/api/version.js` へのGETリクエストに対し、`version.py` の値を元に JavaScript ファイルを動的生成・レスポンスする。
3. **`version.js` の出力内容例**:
   ```javascript
   // Auto-generated by local_sync_server.py from version.py
   self.APP_VERSION = "1.1.0";
   self.WEB_PET_CACHE_NAME = "neo-pet-v1.1.0";
   ```
4. **Service Worker (`sw.js`) での連携**:
   Service Worker 冒頭で `importScripts('./version.js');` を実行。
   ```javascript
   importScripts('./version.js');
   const CACHE_NAME = self.WEB_PET_CACHE_NAME || 'neo-pet-v1.1.0';
   ```
5. **フロントエンド (`pet.js` / `index.html`) での連携**:
   - `pet.js` のキャッシュパージ処理:
     ```javascript
     if ('caches' in window && window.WEB_PET_CACHE_NAME) {
       caches.keys().then(keys => {
         keys.forEach(key => {
           if (key !== window.WEB_PET_CACHE_NAME) caches.delete(key);
         });
       });
     }
     ```
   - `index.html`: `<script src="version.js"></script>` を最優先で読み込み、以降のスクリプト動的ロードやHTMLテンプレートでのバージョン埋め込みに活用する。

### 2.2 ドメインSeam（継ぎ目）境界と分離設計案

### 2.3 リファクタリング時の安全保証戦略（Seam Pattern）

1. **グローバルオブジェクト / イベントバスによる段階的移行**:
   急激なESモジュール化によるHTML側からのスコープ切れ（`window.prevSuggest` 等の `onclick` 破壊）を防ぐため、当面は `window.NeoPet` 名前空間または直記グローバル参照を維持しながらファイル分割を行う。
2. **依存注入（Dependency Injection）**:
   例えば `pet_agent_bridge.js` から `pet_animator.js` の `triggerCelebrateReaction()` を呼ぶ際、直接依存ではなくイベント（`window.dispatchEvent(new CustomEvent('pet:celebrate'))`）を経由させることで疎結合化を図る。
3. **回帰防止テスト（Characterization Tests）**:
   JavaScript側ユニットテスト（例: Vitest / Jest または E2E Playwright）の導入を検討し、`pet.js` のリファクタリング前後でAPIリクエスト形式やDOM変化に相違がないことを自動検証する。
