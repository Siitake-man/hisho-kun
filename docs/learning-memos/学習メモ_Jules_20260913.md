## 1. 得られた知見と設計リフレクション

### ① バージョン定数散逸（Single Source of Truth 違反）のリスクと対策
- **学び**:
  v1.0.0の時点では、Python側の `version.py` (`__version__ = "1.0.0"`) とフロントエンド PWA (`sw.js`, `pet.js`, `index.html`) のアセットキャッシュキー (`v5.32`) が分離して管理されていました。
- **課題**:
  PWAやフロントエンドアセットを更新した際、`sw.js` の `CACHE_NAME` と `index.html` の `?v=`、`pet.js` の古いキャッシュ削除処理でバージョン不一致が起きると、古いJavaScriptがブラウザにキャッシュされ続け、最悪の場合APIクライアントとサーバー間で通信エラーや描画崩れが発生します。
- **改善策**:
  `version.py` をプロジェクト全体の Single Source of Truth と位置付け、`local_sync_server.py` から動的に `/web_pet/version.js` を配信する設計を採用することで、HTML/JS/ServiceWorkerが自動的に同一のバージョン定数を参照・更新できる構造を学べました。

### ② レガシー大規模フロントエンド (`pet.js` 3,335行) における Seam (継ぎ目) 境界の抽出
- **学び**:
  1つの巨大なJavaScriptファイルに全機能（認証、Canvasパーティクル、Web Audio SE、スプライトアニメーション、ポーリング、承認UI、TODOマトリクス、TTS、音声録音）が密結合している場合、安全にリファクタリングするには「機能の責任範囲」と「依存関係（In/Out）」を明確に可視化することが最優先となります。
- **Seam境界設定のポイント**:
  - `pet_auth.js` (認証・fetchラッパー) や `pet_audio_se.js` (Web Audio API) など、他機能への依存が少なく下層に位置するユーティリティから切り出すことで、高層のロジックへの影響を最小限に抑えられます。
  - グローバルイベント (`CustomEvent` / `window.dispatchEvent`) や名前空間 (`window.NeoPet`) を利用した「疎結合な接続ポイント」を設けることで、既存の HTML `onclick` イベントや既存テストを壊さずに段階的なリファクタリングが可能になります。

### ③ 既存テスト（416件）と安全性の継続担保
- **学び**:
  本プロジェクトには416件におよぶ包括的なテストスイート（Pytest, Xvfb環境でのUIテスト、同期サーバーテスト等）が整備されており、コードの変更時にもリグレッションを即座に検知できます。
- **実践**:
  今回の調査・ドキュメント作成作業においても、常に全テスト（416件）をグリーン状態に保ちつつ作業を遂行するプロセスを徹底しました。
