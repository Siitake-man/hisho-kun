## 🧠 PM・アーキテクト視点での概念解説（What / Why / Where）

### 1. Deep Module（深いモジュール）と Seam（接合面）
- **What**: 外部に対しては「シンプルで扱いやすい小さなインターフェース」を公開し、内部に「複雑な処理や状態管理」を深く隠蔽する設計原則。
- **Why**: 1つのファイルに全UI・全イベントハンドラ・全ダイアログを詰め込むと、わずかな修正で思わぬ副作用（バグ）が生じ、AIや人間の認知的負荷が跳ね上がるため。
- **Where/When**: 設定画面、カレンダー手帳、付箋、DBビューアなどの独立した業務画面を開発・保守する際に適用。

### 2. Web Audio API によるシンセシス（音声合成）
- **What**: 音声ファイル（MP3/WAV）をダウンロードして再生するのではなく、ブラウザ内部のオシレーター（発振器）でリアルタイムに音波を合成して鳴らす仕組み。
- **Why**: ネットワーク遅延ゼロ、外部音声ファイル読み込みエラーゼロで、8-bitレトロゲームのような心地よいチャイム音やタップ音を軽量に再生できる。
- **Where/When**: スマホDesk Pet端末における承認要請アラート、作業完了通知、ボタンクリック音。

## 💡 身近な例えでの理解

- **Deep Module化**:
  > 「何でも屋の巨大な総合受付（1人の担当者が電話・経理・人事・警備を全部こなす）」から、**「各専門部署（人事課、経理課、受付窓口）に部屋を分け、総合受付は案内役だけに専念する」** 組織改編と同じ。
- **Web Audio 倍音合成**:
  > 1本のフルート（基音）だけでは音が細くて騒がしい部屋では聞こえにくいが、**「バイオリン（倍音）を一緒に重ねて演奏する」** ことで、音が分厚くリッチになり、遠くまで透き通って届くようになる仕組み。
